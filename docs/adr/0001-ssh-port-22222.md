# ADR-0001: SSH Port 22222

**Status:** Accepted
**Date:** 2026-03-30
**Deciders:** @yboujraf

## Context

Standard port 22 is the first target for automated brute-force attacks and mass scanning. Moving SSH to a non-standard port eliminates the bulk of opportunistic traffic. This is combined with fail2ban rate-limiting and key-only authentication for defense in depth.

## Decision

SSH runs on port **22222**. This is non-negotiable across all managed hosts.

Port 22 is never opened on any firewall or host.

## Consequences

### Positive

- Eliminates >99% of automated brute-force noise against SSH.
- Reduces fail2ban trigger volume, keeping logs clean and actionable.
- Combined with key-only auth, creates a strong baseline posture.

### Negative

- All playbooks, inventories, and firewall rules must reference port 22222.
- Every `ansible.cfg`, `ssh_config`, and CI/CD pipeline must be configured accordingly.
- New operators must be informed of the non-standard port during onboarding.

## Compliance

| Framework | Control | Relevance |
|---|---|---|
| ISO 27001 | A.13.1.1 | Network controls — non-standard SSH port reduces automated attack surface |
| ISO 27001 | A.9.4.2 | Secure log-on procedures — port change is part of layered authentication hardening |
| NIS2 | Art.21(2)(c) | Physical and network security — SSH port policy enforced across all managed hosts |
