# ADR compliance audit — redis (2026-10-03)

Method: roles/contract_audit (PASS=10 FAIL=0 SKIP=23) + manual walk on the live guest, Prometheus/Loki.

**Service:** `redis` (`roles/redis`, `playbooks/redis.yml`) on `lxc-redis-01` — Redis `8.10.0` (official image), TLS-only (`port 0`, `tls-port 6379`, the platform wildcard), one password, AOF + RDB persistence, 132 client connections (NetBox db 0/1, Nextcloud db 3, Authentik db 2, GitLab db 4), 11 MB used.
**Verdicts:** **PASS** · **GAP** · **N/A** · **NOT VERIFIED**; gaps are **FIX** (this PR) · **PLATFORM** · **PROPOSE** · **OWNER**. Host-level rows identical to the previous audits carry the same verdict.

## Summary — gaps ranked

| # | Checks | Finding | Where it is fixed |
|---|---|---|---|
| 1 | SVC-26, SVC-29 | **One credential for every consumer**: the single `default` user (`~* &* +@all`) serves NetBox, Authentik, Nextcloud and GitLab — a leak in one service exposes the others' sessions and queues; database numbers are a convention, not a boundary. | **PLATFORM** — per-consumer ACL users (own credential in Vault `{svc}/redis`, key-prefix or command scope), rolled out with each consumer's play (recorded since the authentik audit) |
| 2 | SEC-21, GIT-05 | Pin `8.10.0` while `8.10.2` is current. | **FIX** — `redis:8.10.2` (one container recreate ≈ 10 s: clients reconnect; AOF reloads) |
| 3 | INF-33 | No Redis metrics (no exporter): memory, clients per database, evictions, persistence status are invisible. | **PLATFORM** — `redis_exporter` sidecar (SVC-33, monitoring pass) |
| 4 | IDN-17, SVC-37 | No `docs/services/redis.md`. | **FIX** — this PR |
| 5 | SEC-15 | The container starts as root and drops to `redis` (uid 999) — the official entrypoint. | **PROPOSE** — the entrypoint-drop class of OH-19 (#724) |
| 6 | tuning | `maxmemory 0` / `noeviction`: no memory ceiling for the caches. | **PLATFORM** — the per-service tuning pass |
| 7 | SEC-22 / NAM-01 / INF-35 | Writable rootfs; NetBox empty; no alert rule names redis. | **PLATFORM** |
