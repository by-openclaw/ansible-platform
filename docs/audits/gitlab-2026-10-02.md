# ADR compliance audit — gitlab (2026-10-02)

Method: roles/contract_audit (PASS=11 FAIL=0 SKIP=22) + manual walk on the live guest, Authentik, the Traefik host, Prometheus/Loki, the PVE node and the public zone.

**Service:** `gitlab` (`roles/gitlab` + `roles/gitlab_rbac`, `playbooks/gitlab.yml`) on `lxc-gitlab-01` (ct 560) — `gitlab.<domain>` + aliases `registry.<domain>`, `pages.<domain>`, private (routes internal-only), OIDC via Authentik, the Omnibus image as one host-network container (10 runit services), stores on the shared PostgreSQL + SeaweedFS, git-data on a ZFS bind-mount, Service Desk live.
**Verdicts:** **PASS** · **GAP** · **N/A** · **NOT VERIFIED**; gaps are **FIX** (this PR) · **PLATFORM** · **PROPOSE** · **OWNER**. Host-level rows identical to the previous audits carry the same verdict.

## Summary — gaps ranked

| # | Checks | Finding | Where it is fixed |
|---|---|---|---|
| 1 | INF-27–29, INF-32 | **None of GitLab's own logs reach Loki.** The image's tail-to-stdout is off (by design) and promtail only had the journal + auditd jobs, so `audit_json`, `auth_json`, the Rails request logs, gitlab-shell, nginx and the service logs (291 MB under `/var/log/gitlab`, trees 0700 to the service accounts) stayed on the host — for an **audit service** (INF-29: ≥ 90 d). | 4 | SVC-56/57 | CrowdSec: the host runs the agent with the base collections only; the hub's GitLab collection (sign-in brute force, user enumeration) was never wired to the Rails request log. | **FIX** — `timokoessler/gitlab` collection + file datasource (`type: gitlab`) |
