# ADR compliance audit — netbox (2026-10-02)

Method: roles/contract_audit (PASS=11 FAIL=0 SKIP=22) + manual walk on the live guest, NetBox's own shell, Authentik, Prometheus/Loki and the PVE node.

**Service:** `netbox` (`roles/netbox`, `playbooks/netbox.yml`) on `lxc-nbox-01` (ct 520) — `netbox.<domain>`, private (route internal-only), OIDC via Authentik, three containers from the official image (app, rq worker, housekeeping), database on the shared PostgreSQL (`verify-full`), shared Redis (TLS, own databases), service mailbox.
**Verdicts:** **PASS** · **GAP** · **N/A** · **NOT VERIFIED**; gaps are **FIX** (this PR) · **PLATFORM** · **PROPOSE** · **OWNER**. Host-level rows identical to the previous audits carry the same verdict.

| 1 | NAM-01, SVC-18–20, INF-23 | **The CMDB is empty** (no sites, devices, VMs, prefixes, IPs) although every naming/CMDB clause makes NetBox the authority — the inventory (`hosts.yml`, the service catalog, `network.yml`) is the de-facto source today. | 2 | IDN-16 | **The break-glass API token held in Vault does not exist in NetBox** (0 tokens): the image applies `SUPERUSER_API_TOKEN` only when it creates the superuser; the Vault field was dead. | **FIX** — `tasks/rbac.yml` validates the held token through NetBox's shell and mints a new one (v2, hashed) written back to Vault when none validates; 4.7's v2 tokens need a pepper (`API_TOKEN_PEPPER_1`), now minted into `netbox/admin` once and injected — without it NetBox cannot create tokens at all |
| 3 | IDN-09, NAM-16 | `yboujraf` (the daily account) is a superuser although only `adm_yboujraf` is in `netbox-admins`: the login pipeline only touches the user logging in, a flag set earlier stays. | **FIX** — superusers reconciled on every run from people.yml (+ the local `admin`) |
| 4 | INF-33, INF-39 | No application metrics (`METRICS_ENABLED` unset; NetBox ships a django-prometheus `/metrics`). | **FIX** — enabled on the app port, the SVC address added to `ALLOWED_HOSTS`, DOCKER-USER admits the monitoring host, catalog `metrics_port: 8080` → job `netbox` |
| 5 | SEC-21, GIT-05 | Pin `v4.6.8` while `v4.7.2` (2026-09-29) is current (4.7 needs PostgreSQL 15+ — the cluster runs 17 — and the `ltree` extension). | **FIX** — `v4.7.2`; `db_extensions: [ltree]` through the scaffold → `postgres_db_extensions` |
| 6 | IDN-17, SVC-37 | No `docs/services/netbox.md`. | **FIX** — this PR |
| 7 | SEC-15 | The three containers run as root (the official image starts NGINX Unit as root). | **PROPOSE** — register OH-12 (#724) |
| 8 | SEC-22 / INF-35 | Writable rootfs; no alert rule names netbox. | **PLATFORM** |
