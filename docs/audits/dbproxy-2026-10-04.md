# ADR compliance audit — dbproxy (2026-10-04)

Method: roles/contract_audit (PASS=10 FAIL=0 SKIP=23) + manual walk on the live guest, Prometheus/Loki.

**Service:** `dbproxy` (`roles/dbproxy`, `playbooks/dbproxy.yml`) on `lxc-pgpool-01` — HAProxy `3.4.6` (official image, LTS line), TCP routing only: PostgreSQL `:5432` to the member whose Patroni REST API answers `/primary`, Redis `:6379` to the member that answers `role:master`; metrics `:8405`. Stateless. The same guest runs the third Redis Sentinel (`roles/redis_sentinel`).
**Verdicts:** **PASS** · **GAP** · **N/A** · **NOT VERIFIED**; gaps are **FIX** (this PR) · **PLATFORM** · **PROPOSE** · **OWNER**. Host-level rows identical to the previous audits carry the same verdict.

## Summary — gaps ranked

| # | Checks | Finding | Where it is fixed |
|---|---|---|---|
| 1 | ADR services/0004 | The deployment departs from the ADR's options: a TCP router instead of `pgbouncer` / `pgpool-II`, and Redis consumers through the router instead of Sentinel-aware clients. | **PROPOSE** — doc-platform-core #72 (approve by merging) |
| 2 | availability | One endpoint guest: while it is down consumers cannot reach the leader (stateless, restarts in seconds; the members stay reachable for administration). | **OWNER** — a second endpoint with a floating address belongs with the second hypervisor (ADR infra/0009) |
| 3 | INF-29 | PostgreSQL sees the endpoint's address as the client's: the connection log names the role and the database, not the consumer's host. | accepted — every service has its own role; recorded in `docs/services/dbproxy.md` |
| 4 | NAM-01 | NetBox holds no record of the guest. | **PLATFORM** (NetBox population is on hold) |
