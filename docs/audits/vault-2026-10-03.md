**Verdicts:** **PASS** · **GAP** · **N/A** · **NOT VERIFIED**; gaps are **FIX** (this PR) · **PLATFORM** · **PROPOSE** · **OWNER**. Host-level rows identical to the previous audits carry the same verdict.

## Summary — gaps ranked

| # | Checks | Finding | Where it is fixed |
|---|---|---|---|
| 1 | IDN-02, IDN-09 | The Authentik application `vault` carries **no access binding**: any Authentik account can start the OIDC flow (Vault then grants only the `default` policy, but the login exists); every other application is bound to its admin group. | **FIX** — `restrict_to_group: true` on the `vault` entry of `group_vars/all/sso.yml` (the blueprint binds `vault-admins`) |
| 2 | IDN-15, IDN-09 | The OIDC auth config, the `admins` policy and the group alias are written **genesis-only** (`vault_genesis=true`) and blind (`changed_when: true`): no steady-state reconciliation, because the deploy policy cannot read `auth/oidc/*` or `sys/auth`. | **PROPOSE** — extend the `ansible-deploy` policy (a root ceremony: `generate-root` with the key shares) with read on `auth/oidc/*`, `sys/auth`, `sys/storage/raft/configuration`; then `oidc.yml` converges on drift every run |
| 3 | INF-33 | No Prometheus telemetry: Vault serves `/v1/sys/metrics?format=prometheus` once a `telemetry` stanza and `unauthenticated_metrics_access` are set on the listener — the container recreate **re-seals** Vault (unseal with the off-platform key shares). | **OWNER** — one reseal window with gap 4 |
| 4 | SEC-21 | `2.0.4` is the newest of the 2.0 line; `2.1.1` is current (minor). The recreate re-seals Vault. | **OWNER** — same window as gap 3 |
| 5 | IDN-17, SVC-37 | No `docs/services/vault.md`. | **FIX** — this PR |
| 6 | SEC-06 | The unseal key shares and the genesis material sit in the controller's bootstrap file (the sanctioned exception) — custody off-platform is the last SEC-06 item. | **OWNER** |
| 7 | SEC-22 / NAM-01 / INF-35 | Writable rootfs; NetBox empty; no alert rule names vault beyond the probe. | **PLATFORM** |
