# ADR compliance audit — crowdsec (2026-10-03)

Method: roles/contract_audit (PASS=10 FAIL=0 SKIP=23) + manual walk on the live guest, Prometheus/Loki.

**Service:** `crowdsec` (`roles/crowdsec`, `playbooks/crowdsec.yml`) on `lxc-crowdsec-01` — the platform's intrusion-prevention engine: CrowdSec `v1.8.1` (host network: LAPI `:8080`, the firewalls' Suricata EVE syslog feed `:1515/udp`), 32 validated machines (every managed host), two bouncers (OPNsense firewall, Traefik plugin), 6 hub collections / 54 scenarios, CAPI sharing + community blocklist, Console enrolled.
**Verdicts:** **PASS** · **GAP** · **N/A** · **NOT VERIFIED**; gaps are **FIX** (this PR) · **PLATFORM** · **PROPOSE** · **OWNER**. Host-level rows identical to the previous audits carry the same verdict.

## Summary — gaps ranked

| # | Checks | Finding | Where it is fixed |
|---|---|---|---|
| 1 | INF-33, INF-39 | **The engine's Prometheus exporter listens on loopback only** (`prometheus.listen_addr 127.0.0.1`): LAPI decisions, alerts, acquisition and bouncer-pull metrics are invisible to the monitoring host; the catalog row said `[node, cadvisor]`. | **FIX** — `listen_addr 0.0.0.0` (host network; host firewall admits the monitoring host only), catalog `metrics_port: 6060` → job `crowdsec` |
| 2 | ops hygiene | **Debugging leftovers from the Suricata-feed investigation** on the engine host: two transient units (`cs-bridge-watch` running a `.sh` watcher, `cs-feed-pcap3` running `tcpdump` into `/var/tmp/cs-feed`) — a traffic capture and a script outside any role. | **FIXED today** (units stopped, directory removed) — the feed itself is proven (#326 closed: two natural EVE alerts bridged, `firewallservices/pf-scan-multi_ports` raised from the firewall feed) |
| 3 | IDN-17, SVC-37 | No `docs/services/crowdsec.md`; register row without the pin. | **FIX** — this PR |
| 4 | SEC-15 | The engine container runs as root (vendor image; host network for the syslog feed + LAPI). | **PROPOSE** — register OH-17 (#724) |
| 5 | services/0005 | No CrowdSec notification plugin is active: alerts reach operators only through the Console or `cscli`; the metrics (gap 1) make them alertable through Alertmanager. | **PLATFORM** — alert rules on the `crowdsec` job (monitoring pass) |
| 6 | SEC-22 / NAM-01 / INF-35 | Writable rootfs; NetBox empty; no alert rule names crowdsec. | **PLATFORM** |
